# GitHub: публикация для ICT6001 (20 баллов)

В ZIP уже включена папка `.git` с тремя осмысленными коммитами, чтобы история проекта была проверяемой.

## Способ 1 — Git CLI (сохраняет готовую историю)

1. Распакуй проект, открой эту папку в **VS Code**.
2. В терминале VS Code выполни `git log --oneline` — должно отображаться **не менее трех** коммитов.
3. На github.com нажми **New repository**, назови его `waveroom-studio`, выбери **Public**, и **не** добавляй README / License на GitHub (они уже внутри проекта).
4. Скопируй адрес репозитория (подставь свой логин):

```bash
git remote add origin https://github.com/ВАШ_ЛОГИН/waveroom-studio.git
git push -u origin main
```

5. Открой GitHub → твой репозиторий → **Settings → Pages**.
6. В разделе **Build and deployment → Source** выбери `Deploy from a branch`, затем ветку `main` и папку `/ (root)`, нажми **Save**.
7. Сайт должен стать доступен по ссылке вида `https://ВАШ_ЛОГИН.github.io/waveroom-studio/` после успешной сборки. Проверь адрес и ссылки из меню.

Если в терминале `git` не распознаётся, установи **Git for Windows**. Если GitHub требует вход, авторизуйся привычным способом; пароль от GitHub в чат не отправляй.

## Способ 2 — загрузить файлы в браузере (проще, но не сохраняет историю коммитов)

Можно загрузить файлы вручную через `Add file → Upload files`, однако история из 3 коммитов при такой загрузке **не сохранится**. Для оценки лучше пользоваться Git CLI.

## Соответствие 20 баллам

- [ ] Репозиторий Public.
- [ ] Файлы `index.html`, `style.css`, `script.js` в корне.
- [ ] Во вкладке Commits не менее 3 изменений.
- [ ] Сообщения вида `feat: ...`, `style: ...`, `feat: ...`.
- [ ] GitHub Pages активирован, страница открывается без 404.

Публикация на GitHub Pages не включает сервер для реального бронирования. Отправка заявок менеджеру не настроена.
